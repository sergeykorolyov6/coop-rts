# Механика: сетевой кооп (lockstep)

Статус: утверждена (решения Claude по `PLAN.md` M3, просьба Сергея 05.11.2026 «приступай к реализации кооп режима»)

Двое–четверо друзей играют одну миссию на своих компьютерах. Сим уже многопользовательский (`PLAN.md`, раздел 4): сеть только доставляет команды, и все машины считают одно и то же. JTBD из `../vision.md`: «пройти вместе с друзьями» — без выделенного сервера, по IP, как в LAN-играх.

## Допущения

1. Lockstep по `PLAN.md`: машины обмениваются только командами, состояние не передаётся. Детерминизм сима обеспечен правилами `CLAUDE.md` и тестами.
2. Звезда через хоста (решение Claude): один игрок создаёт игру, остальные подключаются к нему по IP. Хост собирает команды всех на ход и рассылает пачку — порядок команд в ходе решает один хост, а не порядок прихода по сети.
3. Транспорт — TCP (`System.Net.Sockets`, без пакетов): трафик крошечный, порядок и доставка гарантированы. Steam Networking — когда будет Steam.
4. Через интернет нужен проброс порта у хоста или виртуальная сеть (ZeroTier, Radmin VPN и т. п.). NAT-traversal и матчмейкинг — не MVP.
5. Не входит: пауза, переподключение выпавшего игрока. Сохранения сетевой игры, продолжение с сохранения по сети и реплеи — в `save-load.md` (просьба Сергея 05.11.2026, решение 88).

## A. Поведение

- **Намерение:** сыграть миссию вместе, каждый за свою базу и фракцию.
- **Input:** меню → «Сетевая игра» → «Создать» (порт) или «Подключиться» (адрес хоста). В лобби каждый выбирает фракцию, хост — миссию; хост жмёт «Начать».
- **Action:**
  - лобби: хост принимает подключения, раздаёт места 1, 2, … по порядку входа, рассылает состав лобби;
  - старт: хост рассылает миссию, seed и фракцию каждого места; у всех стартует одна и та же миссия, каждый управляет своим местом;
  - игра: тики сгруппированы в ходы. Начиная ход k, игрок отправляет хосту свои команды на ход k + задержка; хост, собрав ход от всех, рассылает пачку; машина исполняет ход, только когда пачка этого хода у неё есть. Команды хода исполняются в его первом тике, по номеру игрока, затем в порядке отдачи (`Simulation.Enqueue`).
  - сверка: раз в N ходов каждый шлёт хосту `StateHash`; разошлись — всем «рассинхронизация».
- **Условия:**
  - старт — когда в лобби ровно столько игроков, сколько мест в миссии, и у всех одна версия игры и данных;
  - команда исполняется от имени места, с которого пришла: хост ставит отправителя, а не то, что написано в команде.
- **Результат:** у всех на каждом тике одинаковое состояние.

## B. Данные

### Состояния

Меню → Лобби (хост: ждёт игроков; клиент: подключён) → Игра → (конец миссии | рассинхронизация | хост пропал) → Меню.

Ход в игре: «есть пачка» → исполняем тики хода; «нет пачки» → ждём (на экране «ожидание игроков»), время не копится сверх нескольких тиков.

### Параметры (сетевые константы, не баланс — живут в `Game.Net`)

| Параметр | Значение |
|---|---|
| Ход | 2 тика (0,1 с) |
| Задержка ввода | 3 хода (0,3 с от отдачи до исполнения; для RTS норма 0,1–0,25 с, берём с запасом под интернет) |
| Сверка `StateHash` | раз в 10 ходов (1 с) |
| Порт по умолчанию | 7777 |
| Игроков | до 4 (сколько мест в миссии) |

### Ограничения

- Миссию выбирает только хост; фракцию — каждый себе, из фракций с ролью `player` (`factions.csv`).
- Цвет — по месту (`missions.csv`, `colors`), фракция цвет не меняет: цвет — это игрок (`CLAUDE.md`).
- F1–F4 (переключение игрока на одной машине) в сетевой игре выключены.

### Fail cases

- Другая версия игры или данных (хеш всех json баланса, карт и миссий) → «другая версия игры», соединение закрыто.
- Лобби полное или игра уже идёт → «мест нет».
- Игрок отключился в игре → остальным «игрок N вышел»; игра идёт, его база стоит, его ходы пустые.
- Хост отключился → клиентам «хост отключился», выход в меню.
- Хост получил команду, которую нельзя прочитать → выбрасывает её, остальным не рассылает.

## C. Проверка

### Given / When / Then

| # | Дано | Когда | Тогда |
|---|---|---|---|
| 1 | Хост и клиент в лобби миссии на 2 места | Хост начинает | Оба получают одну миссию, seed и фракции мест 1 и 2; у каждого свой номер места |
| 2 | Идёт игра, задержка 3 хода по 2 тика | Игрок отдаёт команду в начале хода 5 (тик 10) | Команда исполняется на тике 16 у всех машин |
| 3 | Оба игрока отдают команды, 300 тиков | Игра идёт | `StateHash` обеих машин совпадает на каждом тике и с прогоном без сети с теми же командами на тех же тиках |
| 4 | Клиент не прислал ход k | Хост дошёл до хода k | Хост не может исполнить ход k и ждёт; ход пришёл — идёт дальше |
| 5 | Клиент места 2 прислал команду с `PlayerId` = 1 | Хост рассылает ход | Команда исполняется от игрока 2 |
| 6 | Машина клиента разошлась (лишняя команда мимо сети) | Наступила сверка | Обе машины получают «рассинхронизация» с тиком сверки |
| 7 | Игра на 2 игрока | Клиент отключился | Хост получает «игрок 2 вышел» и продолжает без ожидания |
| 8 | Клиент в игре | Хост отключился | Клиент получает «хост отключился» |
| 9 | Хост и клиент с разным хешем данных | Клиент подключается | Клиент получает отказ «другая версия игры» |
| 10 | Миссия на 2 места, в лобби 1 игрок | Хост жмёт «Начать» | Игра не начинается |
| 11 | Хост и клиент по настоящему TCP на 127.0.0.1 | Играют 100 тиков с командами | Хеши совпадают |

### Edge cases

| Ситуация | Решение |
|---|---|
| Команда, которую нельзя прочитать | Хост выбрасывает её (Fail cases) |
| Клиент выбрал фракцию, которой нет или не `player` | Хост игнорирует выбор, остаётся прежняя |
| Сим выдаёт разное в разной культуре системы (русская Windows, английский Mac) | Тест: хеш прогона одинаков при разной `CultureInfo` |
| Кадр долгий (alt-tab), пачки накопились | Догоняем до 5 тиков за кадр, как в одиночной игре |
| Esc в сетевой игре | Меню без паузы: «Продолжить», «Сохранить», «Выйти в меню» (отключает) |

### Что нужно от UI и арта

- Меню «Сетевая игра»: создать (порт), подключиться (адрес и порт), лобби со списком мест, имён и фракций, выбор миссии у хоста, «Начать», «Выйти».
- У хоста в лобби — его адреса в локальной сети, чтобы продиктовать другу.
- В игре: «Ожидание игроков…», «Игрок N вышел», «Рассинхронизация на тике T», «Хост отключился».
