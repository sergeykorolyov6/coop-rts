# Добавление юнита

Юнит существует в трёх местах, и все три должны появиться за один проход. Не делай Sim без префаба и префаб без Sim.

Скилл — для юнитов, которые отличаются статами и простыми компонентами. Поведение, описанное спекой механики (например, стройка рабочим по `Docs/Design/mechanics/drill.md`), реализуется по спеке, а не здесь.

## 0. Вход

- Проверь, что юнит есть в текущей вехе `PLAN.md` (раздел 3 и вехи). Нет — **остановись и скажи**, что это за пределами скоупа.
- Найди строку юнита в `Docs/Design/units.csv`. Числа в CSV — в человеческих единицах. Обязательные колонки:
  `id, name_ru, faction, hp, armor, damage, attack_range, attack_cooldown_s, move_speed, vision, cost_primary, cost_secondary, build_time_s, produced_at, size, tags`
  - `faction` — id из глоссария `CLAUDE.md` (`blue_walls`, `black_legion`, `grey_creatures` …);
  - `attack_range`, `vision`, `size` — в клетках; `move_speed` — клеток/с; `*_s` — секунды;
  - ресурсов в прототипе два; `cost_secondary` может быть 0. Если юнит стоит второй ресурс, а второго типа месторождения на карте ещё нет (он в M2), — юнит реализуй, но отметь в отчёте, что заказать его в игре пока нечем;
  - `produced_at` — id здания, обычно `factory`.
- Если строки нет или колонка пустая — заполни сам по образцу соседних строк и `Docs/Design/balance-notes.md` (референсы SC2 и Mindustry), в `notes` пометь «решение Claude» и перечисли в отчёте. Спрашивай, только если юнита нет в `PLAN.md`.

## 1. Sim (`Assets/Game.Sim`)

- Запусти `python3 Tools/csv2json.py`: он переводит CSV в `Assets/Data/units.json` в единицах Sim (секунды × 20 → тики, клетки × 1000 → милли-клетки, клеток/с → милли-клеток/тик). Если перевод неточный (например, 0,33 с не делится на тик) — скрипт падает с номером строки и колонкой; перенеси это в отчёт, не округляй молча. Новая колонка в CSV — сначала в схему `Tools/csv2json.py`. Sim загружает таблицы через `GameData.Parse`.
- Если юниту нужно новое поведение (не покрытое `UnitBehaviour`: например, осадный урон по зданиям ×3) — добавь компонент в `Entities/Components/`, не наследуйся от `Unit`.
- Все числа — `int`. Никаких `float`.
- Тест в `Game.Sim.Tests/Units/<Id>Tests.cs`:
  - юнит производится за `build_time_s × 20` тиков и списывает ресурсы **из кошелька своего владельца** (не союзника),
  - производится под тем же `PlayerId`, что и здание,
  - двигается на ожидаемое расстояние за N тиков,
  - наносит `damage - armor_цели` (мин. 1) с интервалом `attack_cooldown_s × 20` тиков,
  - не атакует союзников,
  - детерминизм: два прогона сценария с юнитом → одинаковый `StateHash`.
- `dotnet test Game.Sim.Tests` — зелёный, иначе не идти дальше.

## 2. Presentation (через Unity MCP)

- Создай префаб `Assets/Game.Presentation/Prefabs/Units/<Id>.prefab` дублированием `_UnitTemplate.prefab`.
- Геометрия: примитив по `tags` (`melee` → куб, `ranged` → цилиндр, `scout` → сфера, `siege` → усечённая пирамида, `worker` → капсула), масштаб по `size`.
- Цвет — **цвет владельца**, не фракции: общий материал `Unit_Base`, цвет выставляет `UnitView` из `PlayerColors` в рантайме. Отдельных материалов по фракциям не создавай.
- Компонент `UnitView`: поле `UnitId` = `id`.
- Зарегистрируй в `UnitViewRegistry` (ScriptableObject `Assets/Game.Presentation/Registry/Units.asset`).
- Прочитай консоль Unity. Ошибок нет → дальше.

## 3. UI

- В `Assets/Game.Presentation/UI/CommandPanel.uxml` добавь кнопку производства в здание из `produced_at`, иконка — `Icons/<id>.png` (если нет — плейсхолдер `Icons/_missing.png` и пометка в отчёте).
- Хоткей — следующий свободный из `Docs/Design/hotkeys.md`, запиши туда.

## 4. Отчёт

Перечисли: файлы Sim, тесты, префаб, изменения UI, предупреждения конвертера, что осталось человеку (иконка, проверка глазами в Play Mode: цвет совпадает с цветом игрока). Если что-то не сделано — напиши явно.
