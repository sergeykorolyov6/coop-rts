## 1. Видение (кратко)

**Кооперативная PvE-RTS для 1–4 друзей, которые хотят вместе проходить стратегическую кампанию без стресса PvP.** Steam, ПК, мышь и клавиатура. Миссия 30–45 минут. У каждого игрока своя база и стартовая позиция. Реалтайм как в SC2, баланс только под PvE.

**Ядро — точки интереса** (как в HoMM3/WC3). Отдельного правила захвата нет: точка работает на того, кто выполняет её условие, у каждого типа точки своё условие.

**Экономика — по мотивам Mindustry, но ради войны.** Месторождение — область клеток руды с бесконечным запасом. Рабочий строит на нём бур 2×2, дальше бур добывает сам и отдаёт ресурс на конвейер, а конвейер везёт его в штаб. Кто поставил буры и защищает их турелями, тот месторождение и контролирует. Рабочие тоже умеют добывать вручную, но буры гораздо эффективнее. **Ресурсы у каждого игрока свои**, и получает их тот, в чей штаб конвейер привёз ресурс — так игроки делятся друг с другом. Помогать союзнику строить можно бесплатно для себя, а чинит каждый за свой счёт, даже здание союзника (ответ 19). Штаб у игрока один одновременно; разрушенный можно отстроить (ответ 16). Туман войны общий для всей команды.

**Роли мягкие, их три:** Разведчик & Боец, Защитник, Экономист. Любой игрок делает любую роль в разной мере.

**Три JTBD, по которым режем скоуп:** «мой вклад в команде важен» (своя зона ответственности), «тактика, а не скорость кликов», «каждая миссия ощущается новой».

**Фракции различаются тем, куда уходит внимание игрока** — так каждый выбирает себе порог входа, и новичок с опытным игроком играют вместе. Играбельные: Синие Стены (внимания требуют мало, прочность прощает ошибки), Красные Молнии (микроконтроль), Коричневые Мусорщики (экономика и логистика), Жёлтая Звезда (герой, прокачка заново в каждой миссии). Неиграбельные: Серые Существа (нейтральные крипы), Чёрный Легион (основной враг). Все четыре играбельные — **цель на горизонте 3+ лет, в MVP одна.**

## 2. Честная оценка

| Что | Двое, part-time, ~10–15 ч/нед, Claude Code + Unity MCP + скиллы (раздел 10) |
|---|---|
| Играбельный уродливый кооп-прототип (MVP ниже) | 8–12 мес (было 6–9: добавились конвейеры и враг с базой, которая восстанавливается) |
| Одна фракция + 5–8 миссий кампании + минимальный арт/звук — «можно показать людям» | 1,5–2 года |
| Полное видение (4 фракции, кампания, герой, сохранения, голосовой чат, полировка) | 3–4+ года или команда с бюджетом |

Почему ИИ ускоряет не пропорционально: он режет время на написание кода (Sim, тесты, pathfinding, сетевой boilerplate, UI-разметку, сборку сцен через MCP) в 3–5 раз. Он **не** режет плейтесты, итерации баланса, поиск «а весело ли», отладку десинков между двумя машинами и вашу координацию. На MVP код — большая часть работы, поэтому выигрыш большой. На кампании большая часть — контент и дизайн, выигрыш меньше.

Главный риск с ИИ меняется: не «не сможем построить», а «построим быстро много и не то». Защита — вертикальный срез и плейтест в конце каждой вехи.

Главные риски по убыванию:
1. **Сеть.** Lockstep + детерминизм — стандарт жанра, но десинки отлаживать больно. Смягчение: детерминизм закладываем с первого дня, тест на StateHash — обязателен.
2. **Конвейеры.** Решено делать как в Mindustry — это самая большая механика экономики. Спека есть (`mechanics/conveyors.md`): повороты и мосты, без слияний (линии сводит склад), юниты ходят по лентам. Три отдельных риска: (а) UX — протягивание лент мышью должно быть простым, иначе бьём по антимотивации 2 «высокий порог APM»; (б) производительность — тысячи единиц ресурса на лентах в детерминированном симе, нужна модель «лента как очередь», а не «каждая единица — объект»; (в) уклон в автоматизацию — сам референс Mindustry предупреждает «не брать слишком сильный уклон». Проверка на плейтесте M1: сколько времени игроки тратят на ленты против разведки и боя.
3. **Враг с базой.** По ответу брата враг — не «волны по таймеру», а готовая база с настоящим доходом (рабочие и буры на отмеченных точках), которая восстанавливает разрушенное рабочими и расширяется на отмеченные точки с лимитами. Это заметно больший ИИ. Смягчение: в M2 только база, волны и восстановление (ответ 25). Замечание брата: расширение — это то же восстановление, только здания «разрушены» с начала игры. Поэтому восстановление делаем от «слотов базы» (место + тип здания), и точка расширения — это слот, пустой с начала миссии; включить расширение после плейтеста — вопрос данных и лимитов, а не новой механики.
4. **Pathfinding и движение толпы.** Unity NavMesh для RTS не подходит (недетерминирован, плохо с сотнями юнитов). Нужны flow fields + простое избегание столкновений. Известная задача, но её надо сделать самим. Ленты не препятствие (как в Mindustry), так что flow field пересчитывается только при стройке зданий.
5. **Контент.** Каждая фракция = юниты + здания + арт + анимации + баланс. Умножается на количество фракций. Единственная защита — не делать вторую фракцию, пока первая не весёлая.
6. **«Весело ли это».** Узнать можно только плейтестом. Поэтому вехи построены так, чтобы играбельная версия появилась как можно раньше.
7. **Арт.** Никто из двоих не художник. Решение: плоский геометрический стиль. Спека бура требует, чтобы всё было окрашено **в цвет владельца** — это ложится на геометрию идеально: форма по типу, цвет по игроку.

Что стоит пересмотреть в видении:
- **Столпы.** В v0.1 их пять. Спека v0.3 и выбор конвейеров сделали автоматизацию ядром экономики. Предложение для MVP: **Исследование карты + Точки интереса + Оборона + Автоматизация экономики (буры и конвейеры).** Микроконтроль — после MVP. Следить за балансом с автоматизацией — риск 2.
- **Встроенный голосовой чат** — решено: не в прототипе, Discord.
- **Сохранения посреди миссии** (антимотивация 5) — не MVP, но lockstep даёт их почти бесплатно: сохранение = seed + журнал команд (+ снапшот для скорости). Поэтому команды сериализуемые с M0.
- **Сила ИИ от числа игроков** — дешёво: поле в данных волн, делаем сразу в M2.
- **Фракции как выбор порога входа** (редакция 31.10.2026) — сильное решение: отвечает сразу на барьер 3 «разный уровень игроков» и антимотивацию 3 «один тащит всё». Но в MVP одна фракция, поэтому эту идею MVP не проверяет: смешанную по опыту группу можно честно тестировать только со второй фракцией. Отсюда порядок после M4 — вторая фракция с самым непохожим вниманием (Красные Молнии, микроконтроль) раньше остальных. Внутри MVP та же идея — аргумент держать Синие Стены действительно простыми: мало микро, мало обязательной логистики.
- **Формат спеки v0.3** (Допущения / Поведение / Данные / Проверка) — сильная сторона документа. Делаем его стандартом: строки Given/When/Then один к одному становятся тестами Sim. Шаблон: `Docs/Design/mechanics/_TEMPLATE.md`.
- Аудитория из прошлой версии плана закрыта портретом игрока в v0.2.

## 3. Скоуп MVP (веха M4)

Только это. Всё остальное — в бэклог.

- **Игроки:** 2 (архитектура рассчитана на 4, тестируем на 2; соло тоже должно проходиться — «можно полноценно играть одному»).
- **Фракция игрока:** одна — Синие Стены (дорогие, прочные, универсальные; внимания требуют мало, прочность прощает ошибки).
- **Владение:** у каждого игрока свой цвет, свой кошелёк ресурсов, свои здания и юниты. Всё, включая недостроенное, окрашено в цвет владельца.
- **Старт (прототип):** у каждого игрока штаб, 1 строитель (`builder.md`, было — 3 рабочих) и 100 ед. основного ресурса. Это данные миссии, не константа.
- **Юниты (6 + строитель):** строитель игрока (один, строит, чинит, добывает вручную, возрождается — `builder.md`), ремонтник (сам чинит здания и юнитов; вместо рабочего), разведчик (быстрый, слабый, большой обзор), пехотинец (ближний бой), стрелок, тяжёлый (танк), осадный (против зданий/лагерей).
- **Здания (6):** штаб (один на игрока одновременно; разрушен — можно отстроить), завод (производит юнитов), бур (2×2 на месторождении, `mechanics/drill.md`), конвейер (лента с поворотами и мост, `mechanics/conveyors.md`), турель, склад (буфер на линии: сводит несколько лент в одну, в кошелёк не зачисляет). Предел строителей — число на каждое здание в таблице.
- **Стройка и ремонт:** по правилам бура — совместная, с заморозкой, оплата в момент начала; предел строителей растёт с размером и ценой здания. Рабочие чинят любые здания, в том числе союзные; полный ремонт вдвое дешевле постройки, платит тот, кто чинит; скорость ремонта — как стройки (`mechanics/construction.md`).
- **Ресурсы (2):** оба добываются с месторождений бурами и рабочими вручную (`mechanics/manual-mining.md`). Второй входит в цену сильных юнитов и турели (`balance-notes.md`).
- **Точки интереса (3 типа):** месторождение (спека есть), лагерь крипов (`mechanics/creep-camp.md`), нейтральная структура с бафом (спеки нет).
- **Враг:** Чёрный Легион, 3 боевых юнита и рабочий, готовая база на карте (несколько штабов возможны). Настоящий доход: рабочие и буры на отмеченных точках (ленты врага — такие же здания базы, их тоже отстраивают). Восстанавливает разрушенные здания рабочими, атакует волнами объекты игроков, в первую очередь буры и ленты. Лимиты на рабочих, базы и армию; от числа игроков растут лимиты и скорость (данные). Расширение на заранее отмеченные точки — после первого плейтеста (ответ 25).
- **Крипы:** Серые Существа, 2 вида, стоят на месте, атакуют всё, что слишком близко к лагерю, в том числе буры.
- **Карта:** одна, ручная, ~64×64 клеток, 2 стартовые позиции, вражеская база, ~10 точек интереса, из них 4–5 месторождений разного размера (12–40 клеток руды).
- **Миссия:** одна, короче полной (30–45 мин) — целимся в 15–20 минут. Цель — уничтожить базу противника (ответ 23); поражение — когда у команды не осталось ни штаба, ни рабочих.
- **Fog of war:** общий для всей команды, как в SC2 Co-op; месторождение Скрыто → Разведано.
- **UI:** миникарта (значки разведанных месторождений со свободным местом при наведении, метка тревоги «бур атакован»), выделение рамкой, группы (1–5), панель команд, ресурсы, таймер миссии, размещение здания с превью (силуэт, подсветка руды, ожидаемая скорость добычи, красный контур при недоступном месте), протягивание ленты мышью и постройка моста (по `conveyors.md`), силуэт запланированной стройки, шкала стройки с числом рабочих и значком заморозки, уведомления («место занято», «бур атакован»), видимое состояние бура (работает / склад полон).

Нет в MVP: герой, вторая фракция, кампания и открытие юнитов, катсцены, апгрейды, сохранения посреди сетевой игры (локальные — есть, `save-load.md`), встроенный голосовой чат (Discord), матчмейкинг, расширение врага на новые точки (после первого плейтеста, ответ 25), звук (кроме заглушек), арт кроме геометрии.

## 4. Архитектура

```
[Ввод игрока] → Command → Game.Net (lockstep) → Game.Sim.Tick() → State + SimEvents → Game.Presentation (рендер, UI, уведомления)
```

- **Game.Sim** — чистый C#, детерминированный, целочисленный, 20 тиков/сек. Тестируется без Unity (`dotnet test`). Здесь живёт 70% сложности проекта, и здесь Claude Code наиболее полезен.
- **Многопользовательский с первого дня.** У каждой сущности есть `PlayerId`, у каждого игрока свой кошелёк, отношения (союзник/враг/нейтрал) лежат в состоянии матча. Ресурс зачисляется в кошелёк владельца штаба, который его принял, — не владельцу бура или ленты. Кооп-сценарии (совместная стройка, мой бур на ленте союзника) тестируются в Sim двумя-четырьмя игроками без сети: сеть потом только доставляет команды.
- **Конвейеры** в Sim — очереди ресурсов на сегментах ленты с целочисленными позициями, а не отдельная сущность на каждую единицу ресурса. Иначе тысячи объектов на лентах съедят и тик, и `StateHash`.
- **Lockstep:** каждый клиент собирает команды на тик T, рассылает всем, все исполняют тик T только когда получены команды всех игроков. Задержка ввода ~100–200 мс — для RTS норма. Трафик крошечный, реплеи бесплатно, сохранения позже — на том же журнале команд.
- **События сима.** Уведомления спеки («место занято», «бур атакован», «стройка заморожена») — это `SimEvent`, которые сим порождает, а Presentation показывает. Сим не знает про UI.
- **Данные.** Брат пишет числа в человеческих единицах (секунды, ед./с, клетки). Конвертер в `Tools/` переводит их в тики и милли-единицы → `Data/*.json`. Sim видит только целые. Дробные скорости — через аккумуляторы, без дробных чисел (пример в приложении к `drill.md`).
- Транспорт: сначала LAN/direct через LiteNetLib или Unity Transport; Steam Networking — когда будет Steam.
- **Presentation** интерполирует между тиками, читает `Sim.State`, отправляет команды. Никакой логики. Цвет объекта — цвет владельца.

Альтернатива, если lockstep не осилим: host-authoritative (хост считает сим, рассылает снапшоты). Проще в отладке, но плохо масштабируется по юнитам и требует переписать сеть. Решение принимаем на вехе M3, сим в любом случае остаётся чистым и потиковым.

## 9. Как работать с Claude Code

- Задачи ставить по вехам, по одной: «M1: реализовать бур по `drill.md`».
- **Механику — только по утверждённой спеке.** Первым шагом Claude переводит строки Given/When/Then и Edge cases в тесты и показывает их, потом пишет реализацию. Мелкие вопросы спеки Claude решает сам по порядку «ответы брата → PDF → референсы» и помечает «решение Claude».
- Сим-логику и тесты делегировать полностью. `Game.Sim` — обычный .NET-проект, Claude Code гоняет `dotnet test` без Unity: цикл секунды, не минуты.
- Presentation и сцены — через Unity MCP (см. ниже). Проверять глазами в редакторе после каждой сборки сцены.
- Крупные геймдизайн-решения (новая механика, фракция, скоуп) — за братом. Мелкие Claude решает сам и записывает в `open-questions.md`; брат может поправить.
- Баланс — через данные, не через код.
- Раз в веху: ревью архитектуры Sim на утечки `float`/недетерминизма; ревью контекста (`/context`) — скиллы не должны съедать бюджет.

## 10. Инструменты для Claude Code (что подключать)

Состояние на август 2026. Всё ниже проверять по репозиториям перед установкой — область меняется ежемесячно.

### 10.1. Unity MCP — обязательно

Без него Claude Code видит только файлы на диске. С ним — сцену, иерархию, компоненты, консоль, компиляцию, тесты Unity. Именно это закрывает дыру «сцены и префабы руками».

| | Официальный Unity MCP | CoplayDev/unity-mcp |
|---|---|---|
| Кто | Unity, в пакете `com.unity.ai.assistant` | сообщество, MIT |
| Цена | нужна подписка/триал Unity AI beta + проект в Unity Cloud | бесплатно |
| Требования | Unity 6.0+ | Unity 2021.3–6.x, Python 3.10+ / uv |
| Что умеет | сцены, GameObjects, компоненты, скрипты, консоль, build settings, кастомные тулы на C# | 47 тулов: сцены, ассеты, скрипты, тесты, профайлер, билды |
| Статус | бета, может меняться | активно, v10 (июнь 2026) |

**Рекомендация: начать с CoplayDev** — бесплатно, зрелый, без привязки к облаку. Официальный — если и так купите Unity AI (там же UI Generator, Sprite Generator и т.п.).

Установка CoplayDev: пакет в Unity через Package Manager по git URL, затем `claude mcp add` — инструкция в README репозитория. После подключения первая команда для проверки: «прочитай консоль Unity и перечисли ошибки».

### 10.2. Скиллы Unity — обязательно один набор

Проблема, которую решают: Claude уверенно пишет Unity-код под устаревшие API, который компилируется и выглядит правильно. Скиллы — выжимка актуальной документации с паттернами «неправильно/правильно».

- **Nice-Wolf-Studio/unity-claude-skills** — плагин, 35 скиллов по документации Unity 6.3 LTS, формат WHEN/WRONG/RIGHT/GOTCHA, прогрессивная загрузка. Основной кандидат. `claude --plugin-dir ./unity-claude-skills`.
- **mindrally/skills → unity** — один компактный скилл. Запасной вариант, если 35 скиллов окажутся тяжёлыми для контекста.
- Общие «game developer» скиллы — для нас низкая ценность, не ставить.

### 10.3. Свои скиллы проекта — писать по ходу

Скилл проекта = повторяемый многошаговый workflow. Лежат в `.claude/skills/<name>/SKILL.md` (в другом месте Claude Code их не видит). Пишем, когда workflow повторился дважды:

- `add-unit` — из строки в `Docs/Design/units.csv` создать: данные в Sim, тест, префаб через MCP, запись в UI-панель. **Уже есть:** `.claude/skills/add-unit/SKILL.md`.
- `implement-mechanic` — из утверждённой спеки в `Docs/Design/mechanics/`: проверить, что нет открытых вопросов → тесты из Given/When/Then и Edge cases → реализация в Sim → `SimEvent` для уведомлений → список UI-требований для Presentation. Писать после бура: это будет первая механика по спеке.
- `add-poi` — то же для точки интереса (вероятно, частный случай `implement-mechanic`).
- `desync-hunt` — прогнать реплей на двух сборках, найти первый тик с расхождением `StateHash`, продифать состояние, найти виновника (`float`, порядок итерации, рандом вне RNG).
- `scene-check` — после сборки сцены через MCP: объекты без компонентов, ошибки консоли, отсутствующие ссылки.
- `balance-pass` — брат меняет данные → Claude запускает headless-симуляцию N волн и выдаёт таблицу: сколько прожила база при разных составах.

### 10.4. Хуки — рано и обязательно

В `.claude/settings.json`:

- `PostToolUse` на Edit/Write в `Assets/Game.Sim/**` → `dotnet test Game.Sim.Tests`. Сим не ломается незаметно.
- `PostToolUse` на те же файлы → grep на `float|double|System.Random|DateTime|UnityEngine` внутри `Game.Sim`, при попадании — стоп с сообщением. Детерминизм как линтер, а не как надежда.
- Опционально `PreToolUse` на Bash с `git push` → запрос подтверждения.

### 10.5. Что не нужно

- GitHub MCP — Claude Code работает с git напрямую.
- Photon Quantum — только если на M3 сдадимся с собственным lockstep.
- Генераторы 3D/текстур — графика геометрическая, шейдер с flat-цветом владельца закрывает всё.
